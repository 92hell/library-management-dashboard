# Test catalogue

Generated by `scripts/generate-test-catalog.py` from the test names - do not edit by hand.
Each line is one test; together they are the specification of the system's behaviour.

Run everything: `mvn clean verify` (backend) and `cd frontend && npm test` (frontend).
Totals: 119 backend test methods (parameterised ones run once per case), 36 frontend tests.


## Backend (JUnit, `src/test/java`)

Integration tests boot the whole app on H2 in MariaDB mode with the real Flyway migrations;
each test runs in a rolled-back transaction. Shared helpers live in `support/`.

### Customer self-registration
`src/test/java/com/helmifr/library/account/RegistrationTest.java`

- a new customer gets a CUSTOMER account and a new library card
- a walk-in member links their card (and loan history) with card ID + the email on file
- ...or with card ID + the phone on file, written in another format (+62 / 0 prefix)
- a card ID alone is not enough: neither email nor phone match -> generic error
- a card that already has an online account cannot be linked again
- registering without a card ID, with the email of an unlinked walk-in card, asks for the card ID
- usernames are unique (case-insensitive) and passwords need 10+ characters

### Authors API
`src/test/java/com/helmifr/library/author/AuthorApiTest.java`

- update targets the id in the URL; ids and flags in the body are ignored
- updating an unknown author is a 404, not an accidental insert
- deleting is a soft delete: the author disappears from reads
- an author who still has books cannot be deleted (409)
- invalid input returns 400 with an error per field

### Books API
`src/test/java/com/helmifr/library/book/BookApiTest.java`

- creating a book links its author and stores categories as a list
- unknown categories are rejected; an unknown author is a 404
- search matches title, publisher, category or author and treats % and _ literally
- an unknown sort field is a 400, not a server error
- page size is capped so clients cannot request unbounded pages
- books show onLoan, and a book on loan cannot be deleted (409)
- customers can browse the catalogue

### Copies and barcodes
`src/test/java/com/helmifr/library/book/CopiesTest.java`

- a new book can be added with several copies, each with its own barcode
- a title with 2 copies can be lent to two members at once, not three
- desk checkout by barcode lends exactly that copy; a copy already out is refused
- returning by barcode closes that copy's loan; unknown or idle copies are reported
- looking up a barcode shows the title and who has the copy
- librarians add, relabel and withdraw copies; barcodes are unique and a lent copy stays
- approving a request hands over an available copy
- loans can be searched by barcode
- customers see how many copies are on the shelf, but not the copies themselves
- deleting a book withdraws its copies

### Borrow requests: customer requests, librarian decides
`src/test/java/com/helmifr/library/loan/BorrowRequestTest.java`

- a request starts PENDING and shows up in the customer's loans and the librarian queue
- approving lends the book: ACTIVE, borrowed today, due in 14 days
- approval is refused while the book is lent to someone else (409)
- rejecting keeps the reason so the customer can see it
- only pending requests can be approved or rejected (409 otherwise)
- customers can cancel their own pending request, but not someone else's
- a customer cannot request the same book twice while a request or loan is open
- a customer can have at most 3 open requests/loans
- customers only ever see their own loans

### Walk-in loans recorded by a librarian
`src/test/java/com/helmifr/library/loan/WalkInLoanTest.java`

- defaults: borrowed today, due after the loan period (14 days), status ACTIVE
- works for walk-in members without an online account
- a book cannot be lent twice until it is returned
- a past loan can be recorded with its return date (status RETURNED)
- date rules: no future borrow date, return and due dates not before the borrow date
- deleted books cannot be lent (404) and inactive members cannot borrow (400)
- the list filters by status, including derived OVERDUE

### Client address behind Cloudflare
